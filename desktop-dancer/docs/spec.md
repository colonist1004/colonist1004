> ✅ = 결정·구현됨 (2026-11, Part C MVP). 남은 ☐ 항목은 다음 마일스톤에서 결정.

## 0. 프로젝트 공통

### 0-1. 목표와 범위
- ✅ [MVP] 1차 목표: "샘플 캐릭터 + 샘플 춤이 작업표시줄 위에서 돈다"까지를 MVP로 함 → **구현 완료 (Part C MVP)**
- ☐ 최종 목표: 개인용 / 지인 배포 / 공개 배포 / 판매
  - 공개·판매라면 6장(라이선스) 항목이 전부 필수가 됨
- ☐ 우선순위: 캐릭터 품질 vs 춤 품질 vs 앱 가벼움 중 무엇을 1순위로

### 0-2. 실행 환경
- ✅ OS: Windows 11
- ✅ GPU: AMD Radeon RX 9070 XT (VRAM 16GB) — **NVIDIA가 아니라 CUDA 없음**
  - PyTorch는 ROCm으로 Windows 네이티브 / WSL2 모두 공식 지원됨
  - 하지만 3D AI 모델들이 쓰는 CUDA 전용 확장(spconv, flash-attn, torch_scatter/torch_cluster 등)은 ROCm에서 안 되거나 직접 빌드해야 할 가능성이 큼
- ☐ 파이프라인(캐릭터 생성·리깅·춤 추출)을 돌릴 곳:
  - 1안: WSL2 + ROCm에서 시도 (시간 제한 두고 시도, 막히면 2안)
  - 2안: **클라우드 NVIDIA GPU** (RunPod, Colab 등) — 캐릭터·춤은 한 번 만들면 끝이라 사용 시간이 짧음
  - 데스크탑 재생 앱(Part C)은 AMD에서 문제없이 동작
- ☐ 인터넷 없이도 동작해야 하는지 (앱 재생부만? 전체?)

### 0-3. 공통 데이터 포맷 (파트 간 약속)
- ✅ [MVP] 캐릭터 포맷: **VRM 1.0** (VRM 0.x도 재생은 됨)
- ✅ [MVP] 춤 모션 포맷: **VRMA**(VRM Animation 1.0) — Part A/B 파이프라인 출력도 이 포맷으로 맞춤
- ✅ 저장 위치·폴더 구조: 앱 기본 에셋 `assets/characters`, `assets/motions` + 사용자 라이브러리 `%APPDATA%\desktop-dancer\library\{characters,motions}`, 설정 `%APPDATA%\desktop-dancer\settings.json`
- ☐ 캐릭터·모션 메타데이터 파일(이름, 원본 출처, 생성일, 썸네일) 형식: JSON 권장

## Part A. 캐릭터 생성 (이미지 → 리깅된 3D 캐릭터)

### A-1. 입력 이미지
- ☐ 캐릭터 스타일: 애니/카툰풍 / 실사 / 둘 다
- ☐ 입력 조건 규칙: 전신 필수? 정면? T포즈·A포즈? 배경 단색?
- ☐ 입력 장수: 1장 / 앞·옆·뒤 여러 장 (여러 장이면 품질↑, 사용 편의↓)
- ☐ 전처리 자동화: 배경 제거, 크롭, 해상도 맞추기
- ☐ 포즈가 안 맞는 이미지가 들어왔을 때: 거부 / 경고 / AI로 포즈 보정 후 진행

### A-2. 3D 생성 방식
- ☐ 방식: 로컬 오픈소스 모델 / 유료 API / VRoid 등 반수동 제작
- ☐ 후보 모델·서비스 비교 기준: 품질, 속도, VRAM, 비용, **라이선스(상업 이용 가능 여부)**
- ☐ 생성 결과에 바로 뼈대가 들어오는지, 메시만 오는지 확인
- ☐ 텍스처 품질 기준 (해상도, 뒷면 처리)
- ☐ 폴리곤 수 상한 (데스크탑 상시 실행이므로 가벼워야 함, 예: 3~5만 이하)

### A-3. 리깅 (뼈대 넣기) — 가장 막히기 쉬운 단계
- ✅ 리깅 방식: **UniRig** (VAST-AI-Research / 칭화대·Tripo, SIGGRAPH 2025) 로컬 실행
  - 2단계 구조: ① 뼈대 예측 → ② 스키닝 웨이트 예측 → merge 스크립트로 원본 메시에 합치기
  - 요구사항: CUDA GPU, VRAM 8GB 이상
  - 라이선스: 상업 이용 가능한 허용 라이선스 (배포 전 최신 LICENSE 재확인)
- ☐ 설치 환경 (RX 9070 XT 기준):
  - UniRig 의존성: Python 3.11, PyTorch, spconv(CUDA 버전별 패키지), torch_scatter, torch_cluster, flash_attn, bpy(Blender)
  - spconv·flash_attn이 AMD에서 최대 난관 → WSL2+ROCm 시도 후 실패 시 클라우드 NVIDIA GPU에서 실행
  - 클라우드로 갈 경우: 메시 업로드 → 리깅 → 결과 다운로드를 스크립트 하나로 자동화
- ☐ 사용할 체크포인트: 현재 공개된 범용 모델(Articulation-XL2.0 학습) / 사람형·VRoid 데이터로 학습된 체크포인트가 공개됐는지 확인 후 선택
- ☐ 입력 전처리: UniRig에 넣기 전 메시 정리(정점 병합, 면 수 축소, 원점·크기 정규화, T/A포즈 확인)
- ☐ 뼈대 검증 단계: **뼈대가 틀리면 스키닝 품질이 크게 떨어지므로** ①과 ② 사이에 검사 단계를 둘지
  - 자동 검사: 관절 개수, 좌우 대칭, 팔·다리 체인 존재 여부
  - 실패 시: 시드/샘플링 파라미터 바꿔 재생성 N회 / 사용자에게 뼈대 미리보기 후 승인
- ☐ **VRM 휴머노이드 본 매핑 자동화 (UniRig 선택 시 핵심 난제)**
  - UniRig는 사람·동물·사물 공용이라 뼈 이름·구성이 표준이 아님 → 이름이 아니라 **위치·계층 구조로 판별**하는 매핑 스크립트 필요
  - 판별 규칙 예: 최상위 루트 근처 = hips, 위로 이어지는 체인 = spine→chest→neck→head, 좌우로 갈라지는 체인 = 팔, 아래로 갈라지는 체인 = 다리, x좌표 부호로 좌/우 구분
  - VRM 필수 본(hips, spine, head, 양팔·양다리 주요 관절)이 하나라도 안 잡히면 실패 처리
  - 매핑 후 VRM 변환 도구: Blender + VRM 애드온 스크립트 / 기타 변환 라이브러리
- ☐ 매핑이 애매할 때 사용자에게 보여주고 수동 지정하는 UI를 둘지
- ☐ 손가락 뼈 포함 여부 (춤 품질에 영향, 리깅 난이도↑)
- ☐ 스키닝(웨이트) 품질 검수 방법: 테스트 포즈 몇 개로 깨짐 확인
- ☐ 치마·머리카락 등 흔들리는 부분: 무시 / 스프링본(VRM SpringBone) 설정
- ☐ 표정(눈 깜빡임, 입 모양) 블렌드셰이프 필요 여부

### A-4. 결과물·UI
- ☐ 생성 진행률 표시, 소요 시간 안내
- ☐ 실패 시 재시도 / 중간 단계부터 재실행 가능 여부
- ☐ 결과 미리보기 후 저장 / 수동 수정(블렌더로 열기) 경로 제공
- ☐ 완료 기준(테스트): 샘플 이미지 3장 → VRM 파일 생성 → 기본 춤 모션 적용 시 팔다리가 깨지지 않음

## Part B. 춤 모션 추출 (영상 → 애니메이션)

### B-1. 입력 소스
- ☐ 입력 방식: 로컬 영상 파일 / 유튜브 URL 직접 입력
  - URL 다운로드는 유튜브 약관 이슈가 있음 → 개인용이면 로컬 파일 입력을 기본으로 두는 것도 방법
- ☐ 구간 자르기 (시작~끝 시간 지정)
- ☐ 여러 명이 나오는 영상: 대상 인물 선택 UI 필요 여부
- ☐ 입력 영상 권장 조건 안내: 전신, 고정 카메라, 가림 없음, 정면 위주

### B-2. 포즈 추정
- ☐ 방식: 로컬 오픈소스 영상 모션캡처 모델 / 유료 서비스
- ☐ 추출 범위: 몸통만 / 손가락 포함 / 얼굴 표정 포함
- ☐ 처리 시간 허용치 (예: 1분 영상에 10분까지 OK?)

### B-3. 모션 후처리 — 품질 대부분이 여기서 결정됨
- ☐ 떨림 제거(스무딩) 강도 조절 가능하게 할지
- ☐ 발 미끄러짐 보정 (발이 바닥에서 미끄러지는 현상)
- ☐ 바닥 높이 고정, 캐릭터가 바닥을 뚫지 않게
- ☐ 루트 이동 처리: 원본처럼 좌우로 이동 / **제자리 춤으로 고정** (작업표시줄 위라면 제자리 또는 이동 범위 제한 권장)
- ☐ 루프 처리: 끝과 시작을 자연스럽게 이어 반복 재생
- ☐ 원본 인물과 캐릭터 체형 차이 보정 (팔 길이, 키 차이로 손이 몸을 뚫는 문제)

### B-4. 리타게팅·저장
- ☐ 추출한 뼈대 → VRM 휴머노이드 뼈대 매핑
- ☐ 저장 포맷 (0-3과 일치)
- ☐ 음악 함께 저장 여부 (재생 시 음악도 틀지, 춤만 출지)
- ☐ 모션 라이브러리 관리: 이름, 썸네일, 태그, 삭제
- ☐ 완료 기준(테스트): 샘플 댄스 영상 2개 → 모션 파일 → 샘플 캐릭터에 적용 시 떨림·미끄러짐이 눈에 띄지 않음

## Part C. 데스크탑 앱 (작업표시줄 위 재생)

### C-1. 기술 스택
- ✅ [MVP] 엔진: **Electron + three.js + three-vrm / three-vrm-animation**
  - 웹 기술이면 이전 웹 프로젝트 경험을 살리기 쉬움, Unity는 3D 기능이 강하지만 무거움
- ☐ 렌더링 품질: 툰 셰이더(MToon) / 일반 셰이딩 / 그림자 여부

### C-2. 창 동작
- ✅ [MVP] 투명 배경 + 테두리 없는 창 + 항상 위
- ✅ [MVP] 클릭 통과: 캐릭터 외 영역은 뒤의 창이 클릭됨, 캐릭터 위(렌더된 픽셀 알파로 판정)만 잡힘
- ✅ [MVP] 작업표시줄 위치 감지 후 그 위에 붙이기 (`src/placement.js`, 테스트 `scripts/test-placement.mjs`)
  - 작업표시줄이 아래/위/옆일 때, 자동 숨김일 때
  - 멀티 모니터: 어느 모니터에 띄울지 → ✅ 트레이 메뉴 "모니터"에서 선택
  - 화면 배율(DPI 125%, 150% 등)에서 위치 어긋남
- ☐ 전체화면 게임·영상 재생 중 자동 숨김
- ✅ 캐릭터 크기 조절(트레이 메뉴), 드래그로 좌우 위치 이동

### C-3. 재생·동작
- ☐ 재생 모드: 한 곡 반복 / 플레이리스트 / 랜덤 / 시간대별
- ☐ 대기 동작: 춤 사이에 서 있기·숨쉬기 같은 idle 모션
- ☐ 인터랙션: 클릭하면 반응, 마우스 따라 고개 돌리기 등
- ☐ 시스템 오디오(지금 듣는 음악) 박자에 맞춰 춤 속도 조절 여부 — 난이도 높음, 후순위 권장

### C-4. 성능·편의
- ☐ 성능 상한: FPS 제한(예: 30) → ✅ 기본 30, 트레이에서 24/30/60 선택., CPU·GPU 사용률 목표, 노트북 배터리 모드 시 절전
- ✅ 트레이 아이콘 메뉴 (보이기/숨기기, 캐릭터·춤 변경, 크기, 모니터, 속도, FPS, 종료)
- ✅ 윈도우 시작 시 자동 실행 (트레이 메뉴 체크박스)
- ✅ 설정 저장 (크기, 위치, 모니터, 마지막 캐릭터·모션, 속도, FPS)
- ☐ 완료 기준(테스트): 샘플 VRM + 샘플 모션이 작업표시줄 위에서 30분 이상 끊김 없이 재생, 뒤 창 클릭 정상

## Part D. 파트 연결 (통합 구조)

- ☐ 구조: 데스크탑 앱(재생) + 별도 파이프라인(생성·추출) 분리 권장
  - 파이프라인은 Python 기반일 가능성이 높음 (AI 모델들이 대부분 Python)
- ☐ 파이프라인 실행 방식: CLI로 따로 실행 / 앱 메뉴에서 호출 / 로컬 서버(API)로 띄우고 앱이 요청
- ☐ 앱 ↔ 파이프라인 통신 방법, 진행률 전달 방법
- ☐ Python·CUDA·모델 가중치 설치를 어떻게 할지 (설치 스크립트, 용량 안내)
- ☐ 파이프라인 결과물이 저장되면 앱이 자동으로 라이브러리에 추가하는지
