# 파이프라인: 춤 추출 (Part B) · 캐릭터 만들기 (Part A)

> 대부분은 앱의 **춤 만들기** 창(트레이 메뉴)에서 바로 쓰면 됩니다. 설치도 그 창이 자동으로 해 줍니다.
> 아래는 명령줄로 직접 실행하거나 GVHMR을 쓸 때의 안내입니다.

춤 영상에서 동작을 뽑아 VRMA 파일로 저장합니다.
결과는 앱의 모션 라이브러리(`%APPDATA%\desktop-dancer\library\motions`)에 바로 저장되어 트레이 메뉴 **춤**에 자동으로 나타납니다.

입력은 세 가지 중 하나입니다.

| 입력 / 엔진 | 실행 위치 | 품질 | 라이선스 |
|---|---|---|---|
| **RTMW3D** (`--engine rtm`, 기본) | 내 PC. ONNX Runtime이 Windows에서는 DirectML(AMD·인텔·NVIDIA), 그 밖에는 CPU를 씁니다 | 좋음. 133개 키포인트와 깊이 | Apache 2.0 |
| **MediaPipe** (`--engine mediapipe`) | 내 PC CPU | 보통 | Apache 2.0 |
| **BVH 파일** (`.bvh` 를 입력으로) | 외부 서비스에서 처리 | 서비스에 따라 다름 (대체로 가장 좋음) | 서비스 약관을 따름 |
| **GVHMR** (`--engine gvhmr`) | 클라우드 NVIDIA GPU | 높음. 전역 이동까지 복원 | **비상업 전용** |

RTMW3D 모델을 쓸 수 없으면 자동으로 MediaPipe로 진행합니다. 예를 들어 다운로드가 막혔거나 그래픽카드 드라이버에 문제가 있을 때입니다.

### 다른 모캡 서비스의 BVH

웹 모캡 서비스에서 받은 BVH를 바로 변환할 수 있습니다. 대상은 Rokoko Vision(카메라 1대 무료), Plask, DeepMotion, QuickMagic 등입니다.

```bash
python extract_dance.py 춤.bvh --loop
```

- 뼈 이름은 Mixamo, Rokoko, UE, CMU 계열을 자동으로 맞춥니다.
- 단위(cm/m), 위쪽 축(Y/Z), 바라보는 방향, A포즈로 된 기본 자세도 자동으로 보정합니다.

## 설치

앱의 **설치 시작** 버튼이 아래 과정을 자동으로 합니다. uv가 Python 3.12를 직접 내려받으므로 시스템 Python이 필요 없습니다. 명령줄로 직접 하려면 아래 순서로 실행합니다. Python 3.10~3.12가 필요합니다.

```bash
pip install -r requirements.txt
```

```bash
pip install --no-deps -r requirements-nodeps.txt
```

두 번째 줄은 rtmlib를 설치합니다. rtmlib는 onnxruntime과 opencv-contrib를 강제로 설치하는데, 이것이 DirectML용 onnxruntime과 충돌하기 때문에 의존성 없이 따로 설치합니다.

## 사용법

```bash
python extract_dance.py 춤영상.mp4 --start 12 --end 40 --name 내춤 --loop
```

URL도 넣을 수 있습니다. yt-dlp로 내려받으며, 내려받기는 본인이 권리를 가진 영상에만 하세요(유튜브 약관 주의).

```bash
python extract_dance.py "https://www.youtube.com/watch?v=..." --start 5 --end 25
```

자주 쓰는 옵션입니다.

| 옵션 | 설명 |
|---|---|
| `--start`, `--end` | 사용할 구간(초) |
| `--name` | 모션 이름. 기본은 영상 파일 이름 |
| `--loop` | 처음 자세와 가장 비슷한 지점에서 잘라 끝과 시작을 이어 붙임. 반복 재생용 |
| `--root planted` (기본) | 디딘 발을 기준으로 몸이 조금씩 이동 (`--range` 범위 안, 기본 ±25cm) |
| `--root inplace` | 완전히 제자리에서만 춤 |
| `--root original` | 원본 이동 그대로 (GVHMR 전용) |
| `--mirror` | 좌우 반전. 거울 모드 안무 영상에 사용 |
| `--person 1` | 여러 명이 나올 때 대상 지정 (첫 장면 기준 왼쪽부터 0, 1, 2…). 기본은 가장 크게 보이는 사람 |
| `--smooth 2` | 떨림 제거를 더 강하게 (0이면 끔) |
| `--engine mediapipe --model full` | 가벼운 MediaPipe로 빠르게 (`lite`/`full`/`heavy`) |
| `--out 폴더/파일.vrma` | 저장 위치 지정 |

출력은 `<이름>.vrma` 와 `<이름>.json`(원본 출처, 구간, 옵션 메타데이터) 두 파일입니다.

**영상 권장 조건:** 전신이 보이고, 카메라가 고정되어 있고, 몸이 가려지지 않으며, 정면 위주인 영상이 좋습니다.

## GVHMR (클라우드 GPU, 고품질)

1. SMPL-X(https://smpl-x.is.tue.mpg.de)와 SMPL(https://smpl.is.tue.mpg.de)에 가입합니다. `SMPLX_NEUTRAL.npz`, `SMPL_NEUTRAL.pkl` 을 내려받습니다.
2. NVIDIA GPU 클라우드 인스턴스를 띄웁니다. RunPod의 PyTorch 템플릿을 권장합니다.
3. `cloud/` 폴더, 1번의 두 파일, 춤 영상을 올립니다. 그다음 아래 명령을 실행합니다.

   ```bash
   bash cloud/run_gvhmr.sh 춤영상.mp4
   ```

   카메라가 움직이는 영상이면 `--moving-camera` 를 붙입니다.
4. 생성된 `춤영상.gvhmr.npz` 를 PC로 내려받은 뒤 아래 명령을 실행합니다.

   ```bash
   python extract_dance.py 춤영상.mp4 --engine gvhmr --gvhmr-result 춤영상.gvhmr.npz --loop
   ```

GVHMR 공식 Colab 데모로 만든 `hmr4d_results.pt` 도 `--gvhmr-result` 에 바로 넣을 수 있습니다. 이 경우 `torch` 가 설치되어 있어야 합니다.

## 처리 과정

1. **포즈 추정**
   - MediaPipe의 2D 랜드마크(정확함)와 3D 랜드마크(깊이가 부정확함)를 함께 씁니다.
   - x/y는 2D 랜드마크에서 가져옵니다.
   - 깊이는 뼈 길이로 다시 계산하고, MediaPipe 3D는 관절이 앞인지 뒤인지 판단할 때만 씁니다.
2. **보정**
   - 사람이 감지되지 않은 프레임은 앞뒤 프레임으로 보간합니다.
   - 카메라 기울기를 보정합니다. 평균 몸통 방향을 수직으로 맞춥니다.
   - 떨림을 제거합니다. 앞뒤 프레임을 함께 보고 부드럽게 만들어 지연이 생기지 않습니다.
3. **리타게팅**: 관절 위치를 VRM 휴머노이드 뼈 회전으로 바꿉니다. 팔꿈치와 무릎은 굽힘 평면으로 비틀림을 정합니다.
4. **바닥 처리**: 발목과 발끝이 바닥 아래로 내려가지 않게 엉덩이 높이를 맞춥니다.
5. **발 고정**
   - 디딘 발을 감지해 그 자리에 고정하고, 다리를 IK로 다시 계산합니다.
   - planted 모드에서는 디딘 발 기준으로 몸을 이동시킵니다.
6. **루프** (`--loop`): 처음 자세와 가장 비슷한 지점에서 자르고, 남은 차이를 0.5초에 걸쳐 서서히 맞춥니다.

## 알려진 한계

- **MediaPipe 정확도:** 손이 몸 앞에서 카메라 쪽을 향할 때(깊이 방향) 오차가 큽니다. 빠른 회전이나 뒤돌기에서는 좌우가 뒤바뀔 수 있습니다. 이런 영상은 GVHMR을 쓰세요.
- **점프:** MediaPipe 엔진은 점프를 복원하지 못합니다. 항상 한 발이 바닥에 붙습니다. GVHMR 엔진은 점프를 유지합니다.
- **캐릭터 체형 차이:** 발 고정은 기준 체형으로 계산합니다. 체형이 많이 다른 캐릭터에서는 발이 조금 미끄러질 수 있고, 손이 몸을 뚫는 문제도 아직 보정하지 않습니다.
- **추출 범위:** 손가락과 표정은 추출하지 않고, 음악도 저장하지 않습니다.

# 캐릭터 만들기 (Part A)

앱의 **캐릭터 만들기** 창(트레이 메뉴)에서 순서대로 따라 하면 됩니다. 아래는 각 단계가 하는 일과 명령줄 사용법입니다.

```
그림 1장 ──(클라우드 GPU)── TRELLIS: 3D 메시 + 텍스처
                          └ UniRig: 뼈대 + 스키닝 웨이트 → rigged.glb
          ──(내 PC 또는 클라우드)── make_character.py → VRM 1.0 (애니풍 MToon)
```

## 1. 그림 확인 (내 PC)

```bash
python check_image.py 캐릭터.png
```

해상도, 배경, 전신이 보이는지, 정면인지, T/A 포즈인지를 MediaPipe로 확인합니다. 그림체에 따라 자세를 인식하지 못할 수 있어서 결과는 경고로만 알려줍니다.

## 2. 클라우드에서 3D + 리깅 (`cloud/run_character.sh`)

1. NVIDIA GPU(VRAM 16GB 이상) 인스턴스를 준비합니다. RunPod의 PyTorch 템플릿을 권장합니다.
2. 이 `pipeline` 폴더 전체와 그림을 올립니다.
3. 아래 명령을 실행합니다.

   ```bash
   bash pipeline/cloud/run_character.sh 캐릭터.png
   ```

첫 실행은 TRELLIS와 UniRig 설치 때문에 20~30분, 이후에는 캐릭터당 3~5분 걸립니다. 결과로 `캐릭터.vrm`(바로 사용 가능)과 `캐릭터.rigged.glb` 가 생깁니다. 뼈대가 사람 형태로 인식되지 않으면 UniRig 뼈대를 다른 seed로 최대 4번 다시 만듭니다.

## 3. VRM 변환 (`make_character.py`)

뼈대가 **있는** GLB는 그 뼈대를 그대로 씁니다(UniRig 결과 등). 뼈대가 **없는** GLB는 내 PC에서 자동으로 리깅합니다. Tripo나 Meshy 같은 웹 생성기 결과, TRELLIS 결과 등이 여기에 해당합니다. 그래픽카드와 상관없이 CPU만 씁니다.

자동 리깅 순서는 아래와 같습니다.

1. **자세 찾기**: 메시를 15°마다 돌려 가며 렌더링하고, 각 장면에서 MediaPipe로 사람 자세를 찾습니다.
2. **정면 고르기**: 얼굴이 보이고 어깨가 가장 넓게 보이는 장면을 정면으로 고릅니다.
3. **관절 위치 정하기**: 그 장면의 2D 관절 위치에, 메시에서 잰 깊이를 더해 3D 관절을 만듭니다.
4. **스키닝 웨이트 계산**
   - 먼저 각 정점을 가장 가까운 뼈에 붙입니다. 거리는 팔다리 굵기로 나눈 값을 씁니다.
   - 팔은 자기 축 가까이나 어깨 바깥쪽 정점만 가져갑니다. 그래서 겨드랑이 옷자락, 긴 머리, 옆의 소품은 팔에 붙지 않습니다.
   - 마지막으로 열 확산(heat diffusion) 방식으로 관절 주변을 부드럽게 섞습니다.
5. **자세 인식 실패 시**: MediaPipe가 사람을 못 찾으면 몸 모양으로 뼈대를 추정합니다(다리가 갈라지는 높이, 목이 가장 가는 곳 등).

```bash
python make_character.py 모델.glb --name 내캐릭터
```

들어 있는 뼈대가 이상하면 `--autorig` 를 붙여 새로 만듭니다.

Seed-san을 A포즈로 바꾸고 뼈대를 지운 모델로 시험한 결과는 아래와 같습니다.

- 관절 위치 오차는 평균 약 5cm(키 160cm 기준)이고, 앞뒤와 좌우는 정확했습니다.
- 팔을 수평에 가깝게 벌린 모델은 T포즈 보정 후 결과가 깔끔합니다.
- 팔이 거의 수직으로 내려간 모델은 T포즈로 펼 때 헐렁한 옷의 겨드랑이 부분이 늘어납니다.

### (뼈대가 있는 GLB) 뼈 찾기 방식

```bash
python make_character.py 캐릭터.rigged.glb --name 내캐릭터 --height 1.6
```

처리 순서는 아래와 같습니다.

1. **뼈대 찾기**
   - UniRig 뼈 이름은 `bone_0…` 처럼 의미가 없어서, 위치와 계층 구조로 VRM 휴머노이드 뼈를 찾습니다.
   - 발: 바닥 근처의 두 말단 뼈 무리를 찾습니다.
   - 엉덩이: 두 다리가 만나는 뼈입니다.
   - 머리: 몸 중심축에서 가장 높은 말단 뼈입니다.
   - 팔: 척추에서 갈라지는 가지 중 좌우 대칭이 가장 잘 맞는 한 쌍을 고릅니다. 한쪽에만 있는 소품은 제외됩니다.
   - 팔꿈치, 손목, 무릎: 사슬 위 비율로 찾습니다. 손목은 손가락이 갈라지는 지점을 우선합니다.
   - 목과 머리 구분: 머리 부분 정점을 실제로 움직이는 뼈(스킨 웨이트)로 판단합니다.
2. **앞쪽 방향**
   - 발끝이 향하는 쪽을 앞으로 보고 +Z로 돌립니다.
   - 결과가 뒤돌아 있으면 `--flip` 을 붙이세요. 앱에서는 **앞뒤가 반대예요** 버튼입니다.
3. **T포즈 보정**: 팔을 수평으로, 다리를 수직으로 펴고 메시를 그 자세로 다시 굽습니다(LBS bake).
4. **VRM 1.0 저장**
   - 뼈 회전 없이 저장하고, 키를 맞추고, 발을 바닥에 둡니다.
   - 음영은 MToon입니다. 애니풍(외곽선 포함)이 기본이고 `--shading soft` 로 바꿀 수 있습니다.
   - 라이선스 메타는 기본으로 '본인만 사용, 비상업'으로 넣습니다.

## 알려진 한계 (Part A)

- **클라우드 스크립트:** `run_character.sh` 는 TRELLIS와 UniRig 공식 안내대로 작성했습니다. GPU가 없는 개발 환경이라 **실제 실행 검증은 아직 하지 못했습니다.** 첫 실행 때 설치 단계에서 손볼 곳이 나올 수 있습니다.
- **UniRig 모델:** 공개된 UniRig 체크포인트는 범용 모델(Articulation-XL2.0)입니다. 사람형(VRoid)으로 학습한 모델이 공개되면 품질이 더 좋아질 수 있습니다.
- **빠진 기능:**
  - 손가락 뼈, 표정(블렌드셰이프), 머리카락이나 치마의 흔들림(SpringBone)은 아직 넣지 않습니다.
  - 뼈 매핑이 애매할 때 직접 지정하는 화면은 없습니다.
- **T포즈 보정 부작용:** T포즈로 펴는 과정에서 어깨와 겨드랑이 메시가 약간 늘어날 수 있습니다.
