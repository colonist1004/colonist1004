# Desktop Dancer — notes for Claude Code

Windows desktop app: a VRM character dances (VRMA) on top of the taskbar.
The full spec is in `docs/spec.md`. ✅ marks decided items, ☐ marks open ones. Ask before deciding open items.
This folder is separate from the photo editor at the repo root and has its own `package.json`.

## Stack and formats (decided)
- Electron 33 + three.js r170 + @pixiv/three-vrm 3 + @pixiv/three-vrm-animation 3, all as devDependencies.
  The renderer libraries are copied into `src/renderer/vendor/` by `scripts/vendor.mjs`, which is git-ignored.
  This is needed because electron-builder strips `node_modules/*/examples`.
- Character format: VRM 1.0. Motion format: VRMA 1.0. Pipelines (Part A/B) must output these.
- Pipelines (Part A/B, Python, likely run on a cloud NVIDIA GPU because the user has an AMD RX 9070 XT without CUDA) stay separate from the app. The app only consumes files from its library folders.

## Pipeline (Part B)
- `pipeline/extract_dance.py` runs the CLI. Math lives in `pipeline/dancer_pipeline/`: `retarget.py`, `lift.py`, `post.py`, `smpl.py`, `vrma.py`.
- `shared/skeleton.json` is the single reference skeleton. It is used by the JS sample generator and the Python pipeline. VRMA rest rotations are identity.
- Coordinates follow VRM 1.0: +Y up, the body faces +Z, character left = +X.

## Studio ("춤 만들기" window)
- `src/studio/` is the UI. `src/pipeline-runner.js` downloads **uv** into `userData/tools`. uv installs a managed Python 3.12 (`userData/python`) and the venv `userData/pipeline-env`, with `requirements.txt` plus `requirements-nodeps.txt` (rtmlib, installed with `--no-deps`). If uv fails, it falls back to a system Python. It then runs `extract_dance.py --progress-json`. The `@@{json}` lines carry progress, done, and error events.
- Motion engines: `rtm` (RTMW3D via ONNX Runtime; DirectML on Windows; falls back to MediaPipe), `mediapipe`, and `.bvh` input (`dancer_pipeline/bvh.py`). The RTMW3D depth sign and scale are calibrated per clip in `pose_rtm.to_keypoints`.
- YouTube needs `yt-dlp[default]` and `deno`. Both are in requirements, and `video.py` points yt-dlp at the deno binary in the venv.
- The renderer never passes raw CLI arguments. `buildArgs()` validates the option object.
- `DANCER_PYTHON=<python>` skips the setup. `DANCER_OPEN_STUDIO=1` opens the window at launch. E2E tests drive the window with Playwright `_electron`.
- userData is pinned to `appData/desktop-dancer` in both dev and packaged builds. The pipeline gets it through `DANCER_DATA_DIR`.

## Character pipeline (Part A)
- `char/gltf_read.py` flattens any rigged GLB into a world-space bind pose. `rig.py` handles posing and bake (LBS).
- `char/humanoid.py` finds VRM bones from geometry. `normalize.py` handles facing +Z, T-pose, scale, and world-aligned joints.
- `char/gltf_write.py` writes VRM 1.0 with MToon. It writes VRM directly, without Blender or UniVRM.
- `char/autorig.py` rigs unrigged meshes on the CPU. It renders views with `char/render.py`, picks the front where MediaPipe finds a person, lifts the 2D joints to 3D with mesh depth, and computes heat-diffusion weights with arm gating. Without MediaPipe it falls back to the geometric `fit_skeleton`.
- Partial bodies (the photo ends at the shins or the waist, or a hand is missing): `best_view` runs a second sweep zoomed onto the body's own axis, so props and missing legs do not fool the front view. A shoulder/hip line fix then turns out the remaining yaw. `fit_to_mesh` pulls the joint chains back inside the front silhouette and returns `loose` bones. Those get no skin weight; their mesh goes to the nearest ancestor that is kept. Arm radii are capped by shoulder width. Test it with `tests/make_char_fixture.py --unrigged --cut-below 0.3|0.55 [--cut-hand --arm-down 0]`.
- A rigged GLB whose skeleton `find_humanoid` rejects falls back to the auto-rig.
- Dance extraction: knees and ankles that are not seen confidently inside the frame (each engine returns `legs`) ease into a standing pose (`post.legs_seen` and `post.stand_unseen_legs`). Dips shorter than 0.3 s are ignored.
- Slider tweaks live in `src/renderer/customize.js`. They are stored per character as `library/characters/<name>.custom.json` and applied at load in both the dancer and the preview. They never modify the VRM.
- Preview any model with `node scripts/preview/preview.mjs model.vrm out.png [--motion m.vrma --t 1.5] [--skeleton]`. Set `NODE_PATH` to the global node_modules for playwright.

## Layout
- `src/main.js`: window, tray, library, IPC. `src/placement.js`: pure placement math.
- `src/renderer/`: rendering, hit-testing (pixel alpha → `setIgnoreMouseEvents`), FPS cap.
- `assets/`: bundled samples, generated by `npm run gen:samples` and shipped as extraResources.
- User library: `%APPDATA%/desktop-dancer/library/{characters,motions}`. Settings: `settings.json` next to it.

## Rules
- Run `npm test` after changes. If the dance or skeleton changes, run `npm run gen:samples` first.
- Rendering changes: verify headlessly with
  `DANCER_SELFTEST=out.png DANCER_FREEZE_T=<sec> xvfb-run -a npx electron . --no-sandbox`
  and look at the PNG.
- The renderer may only read files inside library folders. This is enforced in `read-asset`. Keep it that way.
- Coordinates in main are Electron DIP. Do not multiply by scaleFactor.
- The Windows build runs in `.github/workflows/desktop-dancer-windows.yml`, which produces portable and NSIS exe files.

## Milestones (spec F-1)
1. ✅ C: sample VRM and sample motion play on the taskbar.
2. ✅ B: video → VRMA (`pipeline/`, Python CLI). MediaPipe runs locally. GVHMR runs on a cloud GPU via `pipeline/cloud/`.
   Test with `python pipeline/tests/test_roundtrip.py`. For real-video accuracy, render a known motion with
   `DANCER_RECORD=dir`, extract it, and compare with `pipeline/tools/compare_motion.py`.
3. ✅ A: image → TRELLIS + UniRig (cloud, `pipeline/cloud/run_character.sh`) → `make_character.py` → VRM.
   The mapping, T-pose and VRM writer live in `pipeline/dancer_pipeline/char/` and need only numpy.
   Test with `python pipeline/tests/test_character.py`. Real-model fixtures come from `pipeline/tests/make_char_fixture.py <any.vrm>`.
   The cloud script is not verified on a GPU yet.
4. D: call the pipelines from the app and manage the library.
5. Quality: post-processing, idle and interaction, music.
