# Desktop Dancer — notes for Claude Code

Windows desktop app: a VRM character dances (VRMA) on top of the taskbar.
The full spec is in `docs/spec.md`. ✅ marks decided items, ☐ marks open ones. Ask before deciding open items.
This folder is separate from the photo editor at the repo root and has its own `package.json`.

## Stack and formats (decided)
- Electron 33 + three.js r170 + @pixiv/three-vrm 3 + @pixiv/three-vrm-animation 3, all as devDependencies.
  The renderer libraries are copied into `src/renderer/vendor/` by `scripts/vendor.mjs`, which is git-ignored.
  This is needed because electron-builder strips `node_modules/*/examples`.
- Character format: VRM 1.0. Motion format: VRMA 1.0. Pipelines (Part A/B) must output these.
- Pipelines (Part A/B, Python, likely run on a cloud NVIDIA GPU because the user has an AMD RX 9070 XT without CUDA) stay separate from the app. The app only consumes files from its library folders.

## Pipeline (Part B)
- `pipeline/extract_dance.py` runs the CLI. Math lives in `pipeline/dancer_pipeline/`: `retarget.py`, `lift.py`, `post.py`, `smpl.py`, `vrma.py`.
- `shared/skeleton.json` is the single reference skeleton. It is used by the JS sample generator and the Python pipeline. VRMA rest rotations are identity.
- Coordinates follow VRM 1.0: +Y up, the body faces +Z, character left = +X.

## Studio ("춤 만들기" window)
- `src/studio/` is the UI. `src/pipeline-runner.js` downloads **uv** into `userData/tools`. uv installs a managed Python 3.12 (`userData/python`) and the venv `userData/pipeline-env`, with `requirements.txt` plus `requirements-nodeps.txt` (rtmlib, installed with `--no-deps`). If uv fails, it falls back to a system Python. It then runs `extract_dance.py --progress-json`. The `@@{json}` lines carry progress, done, and error events.
- Motion engines: `rtm` (RTMW3D via ONNX Runtime; DirectML on Windows; falls back to MediaPipe), `mediapipe`, `.bvh` input (`dancer_pipeline/bvh.py`), and `.vmd` input (`dancer_pipeline/vmd.py`, through the same `run_bvh` post-processing).
- VMD conversion:
  - Coordinates: z mirror, quaternion (-x, -y, z, w), 1 unit = 8 cm. Keys are sampled at 30 fps with their Bezier easing.
  - World-aligned chain: VRM hips = 下半身 and spine = 上半身 relative to it. Twist bones fold into the arm.
  - The A-pose arm chain is conjugated by Rz(∓`--mmd-arm-angle`, default 35°).
  - When 足ＩＫ keys move, the legs are solved by two-bone IK with the knee forward; the foot takes the IK bone's rotation, tipped toward つま先ＩＫ.
  - Tests: `tests/test_vmd.py` (FK and IK round trips of the sample dance, Bezier easing, CLI).
  - Morph and camera keys are ignored.
- The RTMW3D depth sign and scale are calibrated per clip in `pose_rtm.to_keypoints`.
- `--smooth` runs 0..4. Up to 2 it is plain Gaussian smoothing. The extra above 2 goes to `post.smooth_rotations_adaptive`, which measures joint speed on a lightly smoothed copy (so jitter does not count) and averages only the slow frames over a window up to ~0.7 s. Fast frames blend back to the motion as it is. Test: `test_very_smooth_keeps_fast_moves`.
- YouTube needs `yt-dlp[default]` and `deno`. Both are in requirements, and `video.py` points yt-dlp at the deno binary in the venv.
- The renderer never passes raw CLI arguments. `buildArgs()` validates the option object.
- `DANCER_PYTHON=<python>` skips the setup. `DANCER_OPEN_STUDIO=1` opens the window at launch. E2E tests drive the window with Playwright `_electron`.
- userData is pinned to `appData/desktop-dancer` in both dev and packaged builds. The pipeline gets it through `DANCER_DATA_DIR`.

## Still poses
- A pose is a motion named `<name>.pose.vrma`: two identical keys, 1 s apart. The tray lists poses under **포즈** and dances under **춤**. The renderer detects still clips (`isStill`), and `life.js` adds breathing (see "Alive layer" below).
- Built-in poses: `scripts/poses.mjs` (Euler) plus `BUILT_POSES` from `src/renderer/poses-data.js` (quaternions; `makeClip` takes either), generated by `npm run gen:samples` and checked by `scripts/check-poses.mjs` (part of `npm test`).
- From a photo: `extract_dance.py photo.jpg` calls `run_photo`, which detects one frame with the same engines. MediaPipe gets lifted with its own bone lengths; RTMW3D skips the per-clip depth-scale fit for a single frame. Legs that are not seen stand. The studio has a dance/pose mode toggle, and an image input switches it to pose. `DANCER_OPEN_STUDIO=pose` opens pose mode.

## Alive layer (`src/renderer/life.js`, `beat.js`, `music.js`)
- `Life` applies offsets after the mixer every frame: blink, cursor look (eyes via `vrm.lookAt.target`, plus neck/head), reactions (click on head or body, 5 clicks for angry, patting = strokes back and forth over the head, dangling while dragged with a pendulum swing), breathing in still poses, and nodding to the beat. `Offsets` restores bones the mixer does not reset, so nothing accumulates. Every offset is written for VRM 1.0, which faces +Z. VRM 0.x models are turned 180° by `rotateVRM0`, so their x and z turns are mirrored (`vrmAxisSign`). Use it for any new procedural rotation, including `idlePose`. `life.reset()` runs before the mixer each frame. Hops move a `holder` group, because customize.js owns the VRM root transform.
- Main sends the cursor position relative to the window (`cursor` IPC, 20 Hz, only on change). Settings `lookAt`, `reactions` and `music` are toggled from the tray's 반응 menu.
- Music: main answers `getDisplayMedia` from the dancer window with the screen plus `audio: 'loopback'` (Windows only). `Music` analyses with an AnalyserNode. `BeatTracker` resamples spectral flux onto an even 100 Hz grid with audio-clock timestamps (timers are irregular), estimates tempo by harmonic autocorrelation and phase with a comb. `clipTempo()` finds the dance's own beat (hips going down plus joint speed). `syncRate()` adds a P term and the renderer adds an I term, then sets `mixer.timeScale`.
- 산책: `src/wander.js` plans the walk (pure, `scripts/test-wander.mjs`). Main slides the window at 60 Hz without saving, then saves `xCenter` when the walk ends. A drag or a placement change ends a walk early. The renderer gets `walk` start/stop: `Life` turns the `holder` ±70° and plays a procedural walk cycle with the hips at standing height, and the dance pauses (`holdFactor`). The renderer sends `busy` while it dances to music, which blocks walks. `DANCER_WANDER_SEC=<s>` sets the interval for tests.
- Alt+drag (renderer `grabPartAt`): raycast the VRM (skinned bounding spheres are recomputed first), then pick the nearest humanoid bone segment; hands = lowerArm/hand, feet = lowerLeg/foot/toes, chest = spine/chest/upperChest; hips/neck/head/upper limbs win as "not grabbable" so those fall back to a window drag. `Life.grabStart/Move/End` runs two-bone IK on normalized nodes after every other overlay (`_twoBone`, the elbow/knee bends the way it already bends) or leans spine+chest (≤0.7 rad). The weight eases in 0.15 s and out 0.8 s (smoothstep). Shift on release pins it (`life.pins`); `release-pins` IPC lets them go. `DANCER_FREEZE_T` still runs `Life` while something is grabbed or pinned.
- Pose save: tray → main `capture-pose` → renderer `capturePose()` (normalized local quaternions plus rest offsets from `normalizedRestPose`, x/z mirrored back for VRM 0.x) → `pose:captured` → `src/vrma-writer.js` writes `내 포즈 N.pose.vrma` into the user library and selects it. `DANCER_SAVE_POSE=<ms>` triggers it for tests.
- Sitting: `Life.setSit('dance'|'rest'|null)` blends legs (and hips height 0.09/0.95 of the rest hips) to the 걸터앉기 pose; 'rest' also sets the arms and slows the mixer. Lower legs swing whenever seated, including still poses that sit (thighs forward, knees bent, hips low). While `life.sitting`, the renderer sends `sitting` (hang = share of the frame height) and main grows the window below the floor (`placement.computeBounds` `hang`, cut by `behindTaskbar`). After a walk that arrives, main sends `rest-sit` (20-40 s, `restSit` setting, `DANCER_REST_SIT_PROB` for tests) and blocks walks meanwhile. `sitDance` setting = sit while dancing.
- Sit styles: `src/renderer/poses-data.js` builds poses from limb directions in the torso frame (`buildPose`: shortest rotations, the lower bone bends from the upper's direction so twist carries over); shared by `SIT_STYLES` (life.js) and `BUILT_POSES`. Setting `sitStyle` ('random' picks one per sit, `Life.setSitStyle`); 'dance' mode takes only leg bones, 'rest' takes all. Swing only for styles with `swing` and thighs side by side (crossed legs never swing). Seat height: `thighRadius()` (60th percentile of mid-thigh vertex distance / thigh length, bind pose) and `Life._seat` put the thigh underside on `life.seatY` = floor line − pad − `sitOffset` px (setting, 위치·크기 window, ±200).
- Window watcher (`src/perch.js`, Windows, always running): a PowerShell child compiles a small C# class (`Add-Type`, C# 5) that prints, on change, `F` the foreground window (DWM extended frame bounds, per-monitor DPI aware, physical px; `full` = covers its monitor; `quns` = SHQueryUserNotificationState), `T` a tracked window, and `L … L end` the visible window list on the `list` command (`track <hwnd>` sets the tracked one). Main converts with `screen.screenToDipRect` (`toDip`). `parseMessage` is unit-tested.
- 게임 모드 (setting `gameMode`, default on): `shouldHideFor` (fullscreen on the character's monitor, or quns 3/4) → `gameHidden` → `applyVisibility()` hides the window and sends `paused` (the renderer skips drawing). Walks are blocked meanwhile. `DANCER_FULLSCREEN_FAKE=onMs,offMs` fakes it.
- Drop onto a window: drag start asks for the list; drag end runs `dropTarget` (feet within 40 px of a visible top edge) → a `manual` perch that tracks that hwnd (keeps its x offset), with `perchPlacement(..., { manual: true })` (any on-screen edge). It ends (back to the taskbar under it, yOffset 0) when the window closes, minimizes, maximizes or leaves the display. `DANCER_WINDOWS_FAKE="x,y,w,h;…"` fakes the list.
- Perch on the window in front (setting `perch`): `perchPlacement` (pure, `scripts/test-perch.mjs`) rejects maximized/fullscreen/tiny/too-high windows. While perched, `boundsSettings()` overrides `floorY`/`xCenter`, walks are off, and the renderer sits ('dance' or 'rest'). A drag leaves the perch, saves the dropped spot, and skips that window until another one is in front. `DANCER_PERCH_FAKE=x,y,w,h` (DIP) fakes a window for tests; the C# compiles with `mcs`.
- Tests: `scripts/test-beat.mjs` (in `npm test`). For E2E, `DANCER_FAKE_MUSIC=<bpm>` feeds a generated drum loop. `window.__dancer()` and `window.__dancerSync()` expose state. On Linux, a click-through window gets no forwarded mouse events, so E2E calls `setIgnoreMouseEvents(false)` first.

## Character pipeline (Part A)
- `char/gltf_read.py` flattens any rigged GLB into a world-space bind pose. `rig.py` handles posing and bake (LBS).
- `char/humanoid.py` finds VRM bones from geometry. `normalize.py` handles facing +Z, T-pose, scale, and world-aligned joints.
- `char/gltf_write.py` writes VRM 1.0 with MToon. It writes VRM directly, without Blender or UniVRM.
- `char/autorig.py` rigs unrigged meshes on the CPU. It renders views with `char/render.py`, picks the front where MediaPipe finds a person, lifts the 2D joints to 3D with mesh depth, and computes heat-diffusion weights with arm gating. Without MediaPipe it falls back to the geometric `fit_skeleton`.
- Partial bodies (the photo ends at the shins or the waist, or a hand is missing): `best_view` runs a second sweep zoomed onto the body's own axis, so props and missing legs do not fool the front view. A shoulder/hip line fix then turns out the remaining yaw. `fit_to_mesh` pulls the joint chains back inside the front silhouette and returns `loose` bones. Those get no skin weight; their mesh goes to the nearest ancestor that is kept. Arm radii are capped by shoulder width. Test it with `tests/make_char_fixture.py --unrigged --cut-below 0.3|0.55 [--cut-hand --arm-down 0]`.
- A rigged GLB whose skeleton `find_humanoid` rejects falls back to the auto-rig.
- Spring bones (`char/springs.py`, auto-rig only, after `normalize`; `--no-springs` turns them off):
  - Long hair is mesh that hangs behind the back, below the chin, and is connected (welded flood fill) to the back of the head; props that reach up past the head do not count. It gets 1–3 chains of 3 bones under `head`.
  - A skirt is mesh below the waist that stands clear of the whole leg and covers at least 7 of 12 sectors around the hips. Leg thickness comes from the shins, because weights are unreliable near a skirt. It gets 8 chains of 2 bones under `hips`, and its fixed part goes to the hips.
  - Colliders sit on the torso, head and thighs. Everything is written as `VRMC_springBone` (`write_glb(spring=...)`), and three-vrm simulates it.
  - Limit: the geometric fallback (no MediaPipe) finds the crotch at a skirt's hem, so it finds no skirt.
- Dance extraction: knees and ankles that are not seen confidently inside the frame (each engine returns `legs`) ease into a standing pose (`post.legs_seen` and `post.stand_unseen_legs`). Dips shorter than 0.3 s are ignored.
- Local 3D generation (the "내 PC 그래픽카드로 만들기" route):
  - `gen_local.py` runs TripoSG or TripoSR (MIT; upstream code pinned in `dancer_pipeline/gen_sources.py`, weights from Hugging Face on first use). The pipeline is rembg (isnet-anime) → model → `char/bake.py`, which drops floaters, decimates, orients (the best of 24 axis rotations by silhouette IoU against the picture mask, toes decide front/back), unwraps with xatlas and bakes a texture. TripoSR's own color field is queried in model space; TripoSG gets the picture projected from the front, with back faces taking the outline colors of the same height.
  - Stubs replace CUDA-only imports: `diso` (TripoSG decodes with marching cubes, `use_flash_decoder=False`) and `torchmcubes` (scikit-image).
  - It runs in its own env `userData/gen-env`, set up by `gen_setup.py`. AMD gets the official Windows ROCm 7.2.1 wheels, read from the repo.radeon.com listing with the SDK first. NVIDIA gets cu128 and the CPU path gets CPU wheels. torch is pinned by a constraints file, then `requirements-gen.txt` is installed, then the sources are downloaded.
  - `pipeline-runner.js` adds `genStatus` (GPU detection via Win32_VideoController), `setupGen` and `runGen`. The char studio chains the generated GLB into make_character (autorig).
  - Tests: `tests/test_gen.py` (CI installs cv2/trimesh/xatlas). For E2E, `DANCER_GEN_PYTHON` and `DANCER_GEN_FAKE=<mesh>` stand in for the model.
  - Not verified here: real weights (Hugging Face is blocked in this sandbox) and an AMD GPU.
- Slider tweaks live in `src/renderer/customize.js`. They are stored per character as `library/characters/<name>.custom.json` and applied at load in both the dancer and the preview. They never modify the VRM.
- Preview any model with `node scripts/preview/preview.mjs model.vrm out.png [--motion m.vrma --t 1.5] [--skeleton]`. Set `NODE_PATH` to the global node_modules for playwright.

## Layout
- `src/main.js`: window, tray, library, IPC. `src/placement.js`: pure placement math. With the setting `behindTaskbar`, the visible rect is the work area instead of the display bounds (`visibleRect`). The window then ends at the taskbar's edge, so a sunk or huge character looks hidden behind the taskbar, with no z-order tricks. The x and y ranges use the same rect.
- `src/renderer/`: rendering, hit-testing (pixel alpha → `setIgnoreMouseEvents`), FPS cap.
- Toon look (`src/renderer/toon/toon.js`, `toon-chunks.js`; settings `toonShader`, `toonStrength`, `toonHairShadow`; tray menu 보기). It wraps each MToon surface material's instance `onBeforeCompile`/`customProgramCacheKey`; outline materials are never patched. It string-patches:
  - `getShading`: a crisp step mixed with the original by `uToonStrength`.
  - `getDiffuse`: `toonShadeColor`, which fakes a shade when shade ≈ lit and warms skin.
  - `dotNL`: the face's sphere normal around the head bone.
  - `shadingShift`: the light map's G channel.
  - `col`: the hair band and the skin terminator line.
  - If an anchor is missing, the shader is left alone with a warning. `scripts/check-toon.mjs` (in `npm test`) checks the anchors against the installed three-vrm.
- Toon lighting: hemisphere 0.62 and sun 2.6 from (2.2, 2.4, 1.4). A light from the front leaves no shade under the ortho camera. Brightness is calibrated so a lit surface is ≈ its albedo (direct ≈ 0.82, ambient ≈ 0.18, because MToon divides by π), and the fake shade is 0.82 × lit × warm. It applies only when something was patched.
- 조명 설정 (`src/lightwin/`, setting `light` = { face, hair, body, shade, sun, ambient, dirX, dirY }, IPC `light:get`/`light:set`, clamped in main and `toon.cleanLight`): uniforms `uFaceGain` (face+eye), `uHairGain`, `uBodyGain` (everything else) multiply `col` at the end of the col chunk (not outlines); `uShadeLift` is the body shade lift; sun/hemi intensities are scaled and the sun moves to (dirX·3.4, dirY·4, 1.4). `DANCER_OPEN_LIGHT=1` opens the window.
- Plain (non-MToon) materials get an MToon stand-in in toon mode (`toMToon`, swapped back when off). The renderer re-applies customize after a swap.
- Alpha as data: `customize.markAlphaData` flags cloth/skin materials that use alpha and have a texture that is more than 20 % half-transparent (game textures keep masks in alpha, so clothes go see-through). Custom `opaque[name]` overrides this, and the char studio material list has a 불투명 checkbox. Forcing opaque sets `transparent=false`, `alphaTest=0`, `depthWrite=true`, so the OPAQUE define gives alpha 1.
- `giEqualizationFactor` is declared but unused in three-vrm 3.5's shader, so the old "low GI" idea does nothing. The ambient light is what flattened the shade.
- Hair shadow: a hair-only `MeshDepthMaterial` pass into a half-res depth texture after `vrm.update` (head moved by life.js), sampled from face fragments about 2.5 cm toward the light. It runs only when a face and hair exist.
- Kinds come from material extras `dancerToon` (read through `parser.associations`; verified that they survive the VRM plugin) or from `kindFromName`. The char studio preview applies the same toon via `view:get-settings`.
- `assets/`: bundled samples, generated by `npm run gen:samples` and shipped as extraResources.
- User library: `%APPDATA%/desktop-dancer/library/{characters,motions}`. Settings: `settings.json` next to it. `settings.update` saves debounced (250 ms); `settings.flush()` runs on `will-quit`. Light slider ranges: `settings.LIGHT_RANGE` (main) and `toon.js` `LIGHT_RANGE` (renderer) must match.

## Rules
- Run `npm test` after changes. If the dance or skeleton changes, run `npm run gen:samples` first.
- Rendering changes: verify headlessly with
  `DANCER_SELFTEST=out.png DANCER_FREEZE_T=<sec> xvfb-run -a npx electron . --no-sandbox`
  and look at the PNG.
- The renderer may only read files inside library folders. This is enforced in `read-asset`. Keep it that way.
- Coordinates in main are Electron DIP. Do not multiply by scaleFactor.
- The Windows build runs in `.github/workflows/desktop-dancer-windows.yml`, which produces the NSIS installer exe (no portable build).
